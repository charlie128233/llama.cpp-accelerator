The memory hierarchy of a modern personal computer is a ladder of trade-offs. At the top sit the CPU registers and the L1 cache, tiny but answering in a nanosecond. Below them the L2 and L3 caches grow to tens of megabytes while their latency climbs to tens of cycles. Main memory, built from DDR5 modules, holds gigabytes but needs around a hundred nanoseconds to deliver the first byte of a request, and its bandwidth depends on how many channels are populated: a single module gives roughly half the throughput of two. At the bottom, an NVMe solid state drive stores hundreds of gigabytes; it reaches several gigabytes per second only when many requests are in flight at once, because each individual read waits tens of microseconds for the flash chips.

Large language models stress every level of this ladder. During text generation, each new token requires reading the weights of the network, so the speed is set less by arithmetic than by how fast those weights can be streamed to the cores. Mixture-of-experts models change the picture: for every token a small router chooses only a few experts per layer, and the rest of the parameters stay untouched. If the hot experts are kept in RAM and the cold ones are fetched from the drive just in time, a model larger than memory can still run at a useful speed.
